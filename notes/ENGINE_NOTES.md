# hplus engine port — notes (hplus_engine.js)

Scope: 0x23f34..0x24508 (object prep helpers, also used by the loader), 0x24508..0x2c20c (3D/raster
engine), 0x2c2a7..0x2c2fb (real-mode pointer helper), 0x2c500 (VBE check), 0x2c845..0x2cd77 (video
layer). Everything follows PORT_CONVENTIONS.md (memory image `HP.M`, `fn_<hex>` names, register
args in eax,ebx,ecx,edx,esi,edi,ebp order). `hplus_engine.js` is generated by concatenating
`engine_p1.js` (math/init/loader/textures), `engine_p2.js` (frame pipeline), `engine_p3.js`
(drawing), `engine_p4.js` (camera/present/text/video).

External hooks the engine needs:
* `HP.fn_e27a(regs)` — main's procedural texture generator (the callback installed at `[0x2438a]`).
  Called from `fn_2438e` via `HP.callTexGen(bh, bl, ecx, edx, ebx, edi)`: `bh=1,bl=id,ecx=0xa,edx=0x24378`
  (descriptor tail), then `bh=0,ecx=0x300,edx=palette` (768-byte RGB palette), then
  `bh=0,ecx=w,ebx=h,edi=pixels,edx=pixels` (w×h 8-bit image written with a 256-byte row stride; the
  loader tiles it to 256×256). Texture descriptors are the 13-byte blocks in the scene data
  (`[0x2436b..0x24377]` after the copy; `[0x2437c]`/`[0x2437e]` = w/h words).
* `HP.videoOut(srcOffset, page)` — host present: copy 320×240 dwords (little-endian 0x00RRGGBB, i.e.
  bytes B,G,R,X) from `M[srcOffset..]` to the screen. `page` alternates 241/0 (the original's VBE
  display-start y); ignore it.
* `HP.dosPrint(str)` — `fn_2c1e6` (DOS print); `HP.setVideoMode13` / `HP.videoTextMode` (optional).
* `HP.fn_2cf9a` is NOT engine (player "glitch" hook used by the timer tick in the core).

## Data structures
* **scene block** (e.g. 0x14544): +0 mode, +4 width(f), +8 height(f), +0xc aspect, +0x10/+0x14/+0x18/+0x1c
  viewport x0,x1,y0,y1 (floats), +0x20 near (-0.1), +0x24 far (-420), +0x28 shade-table mode, +0x2c..0x2e tint,
  +0x30..0x32 base color of the flat-shade ramp, +0x34 focal length, +0x38 total vertices, +0x3c polygons,
  +0x40 line segments, +0x44 visible objects, +0x48/+0x50/+0x54 drawn polys/lines/particles, +0x4c transformed
  vertices, +0x58 sort items, +0x5c texture base index, +0x60 #objects, +0x64 #textures, +0x68 #particles,
  +0x6c light flags (bit0 = spot), +0x70 light pos, +0x7c spot target, +0x88/+0x8c/+0x90 light factors
  (diffuse, z-term, flat depth-shade), +0x94 objects[16]×0x3c, +0x454 textures[8]×0x18, +0x514 particle array.
* **object** (0x3c): +0 'Line'/'Obu!', +4 flags (bit0 counted, bit1 visible (set by culling), bit2 recompute
  normals each frame, bit3 no backface culling, bit8 white lines / shade −1, bit9..), +8 center, +0x14..+0x1c
  rotation angles (int, 16.16 radians), +0x20 radius, +0x24 scale, +0x28 sort bias (-1 = key 0), +0x2c #verts,
  +0x30 #faces, +0x34 verts, +0x38 faces.
* **vertex** (0x3c): +0 flags (bit0 x>x1, bit1 x<x0, bit2 y>y1, bit3 y<y0, bit4 behind near, bit6 transform,
  bit7 used), +4 xyz, +0x10 sx, +0x14 sy, +0x18 cam z, +0x1c 1/z, +0x20 normal(×255), +0x2c u, +0x30 v,
  +0x34 light (1..255, -1 = not computed), +0x38 1/facecount.
* **face** (0x30): +0 draw fn (0x2a92f), +4 filler, +8 visible, +0xc/+0x10/+0x14 vertex ptrs, +0x18 normal,
  +0x24 plane d, +0x28 flat shade (−1 = white), +0x2c texture index. **line face** (0x10): +0 0x2a81b,
  +4 flags (bit0 visible, bit8 white), +8/+0xc vertices. **particle** (0x2c): +0 0x2a86e, +4 xyz, +0x10 1/z,
  +0x14 sx, +0x18 sy, +0x1c z, +0x20 size, +0x28 size factor.
* **texture** (0x18): +0 w−0.5, +4 h−0.5, +8 palette (RGB), +0xc pixels (256×256, 64K-aligned), +0x10
  shade table (pixels+0x10000; 256 rows × 256 dword colors; byte3 = 0xff for near-black entries), +0x14 ambient.
* **camera** (0x6c+): +0 pos, +0xc target, +0x18 up, +0x24 4×4 matrix (rows = input components, +0x54
  translation). **walker** (0x10): +0 t, +4 speed, +8 key byte offset (×0x28), +0xc total size.
* Per-frame buffers (`fn_26230`, from himem, released at the end of `fn_2a2ac` by restoring `[8]`):
  `[0x25a10]/[0x25a14]` sort lists (key,ptr), `[0x25a18]` clipped faces, `[0x25a1c]` clipped vertices;
  `[0x2a238]/[0x2a23c]` = current write pointers. Screen-clip temporaries are allocated after the near-clip
  vertices and released per polygon.
* Buffers: 320×240×32 bpp back buffers (0x4b000 bytes; effects allocate them), pitch 1280.
* Globals worth knowing: `[0x28e64..0x28e74]` = 1,2,3,4,16; `[0x268e0]`=65536, `[0x2806c]`=65536,
  `[0x28068]`=0.5, `[0x28070]` clamp table, `[0x251b8]`=4 (sort-key z scale), `[0x26400]`=1.5 (lines),
  `[0x28810]/[0x28910]` particle level scale/offset tables, `[0x29090]` flat shade ramp, `[0x26994]` 1/n.

## Rendering pipeline (fn_2a2ac)
camera matrix → frustum culling per object (`fn_251e0`, sets flag bit1) → per-frame buffers → viewport
constants → per visible object: object matrix (`fn_24fc4` from 16.16 angles/65536) × camera (`fn_2515e` →
0x24d10); Lines: transform, near clip lines, project, add to sort list (key = 0xffff − 4·1.5·Σ(z−zmax));
Obu!: backface culling with the camera position in object space (`fn_2589c`, flag bit3 disables), transform,
light setup (`fn_27d90`), near-plane polygon clipping into the temp object 0x2a270, project, sort-list insert
(flat shade = normal·(camera z row) for flat fillers), per-vertex lighting (`fn_28002`) for textured fillers
→ particles → `fn_2a7d0`: radix sort ascending key (far → near), dispatch; polygons are screen-clipped
(Sutherland-Hodgman, fan triangulation) then filled. Textured filler: perspective-correct, 16-pixel sub-spans
with linear interpolation inside, color = shadeTable[light][texel]; additive variant adds the texel to the
blue byte only. Lines and particles are additive on the blue byte (white lines via a saturation table).
If a textured polygon's three vertex lights are all exactly 1.0 it is flat-filled with shadeTable[0][0].

## x87 / exactness notes (validated against the emulator)
* `fn_24dea` is b×a (x87 `fsubrp` operand order). The camera "right" vector is therefore dir×up reversed.
* `fn_2a7d0` switches the x87 rounding mode to **truncate** for the whole draw loop: every `fistp` is
  `Math.trunc` and — importantly — every `fstp dword` truncates toward zero (`HP.wrfTrunc`, used for all
  float32 stores in engine_p3.js). Outside the draw loop `fistp` is round-half-even (`HP.roundHalfEven`).
* NaN: the x87 "real indefinite" is 0xffc00000 (negative) and `fistp(NaN)`/overflow gives 0x80000000 —
  `HP.wrf` canonicalises NaN and `HP.roundHalfEven`/`HP.truncInt` return -2^31 (added to hplus_core.js).
  These matter: effect A's second scene has a degenerate spot light (0/0) and the sign of that NaN decides
  the light clamp branches.
* The textured inner loop keeps u/v/light in registers across 16-pixel spans with a 3-register carry chain
  (`add ecx; adc edx; adc bl`); ported bit-exactly (`pixelLoop`). Texture pointers are 64K aligned; u/v
  integer parts live in the low 16 bits of the texture pointer.
* Remaining non-exactness: x87 80-bit intermediates vs JS doubles (≈1 float32 ulp, probability ~2^-29 per
  stored value) — not observed in the tests so far.

## Validation (test_engine.js + capture_engine_tests*.py)
Function-level differential tests: the emulator snapshot (offsets 0..0xc00000) at function entry is loaded
into `HP.M`, the JS function is run with the entry registers, and all memory is compared with the snapshot
taken at the function's return (ignoring the x86 stack, the timer-IRQ variables `0x2ee00-0x2ee64`, the
music player/sound-driver state and the v86 register block, which change asynchronously).
Results (engine_tests/, first 3 s of the intro): engineinit_0, loader_0/1, sceneinit_0, texgen_0,
camspline_0, render_0, render_1, present_0/1, walker_0 — **all bit-exact**. render_0 = lines + flat cubes,
render_1 = the lit/clipped second scene (near & screen clipping, lighting, sorting).
engine_tests2/ (captured by capture_engine_tests2.py at t = 12, 30, 50, 70, 90, 110, 130, 150, 170, 190,
210, 230 s — effects A..F, textured/additive polygons, particles, lit scenes): render_638/2145/3944/4843/
5882/7622/8942, walker_1604/367867/3510011, camspline_715/1858/2884, present_1181/2436 — **bit-exact**.
render_3461/3645/5226/5435/5652: the frame buffers and all engine state are identical except 2–4 clipped-
vertex u/v/l floats per frame that differ in the last bit (e.g. 0.8125 vs 0.81249994): under RC=truncate an
interpolated attribute whose exact value is representable lands on either side of it depending on whether
the x87's 64-bit or the double's 53-bit intermediate is used — a genuine 80-bit artifact, no pixel impact
in any tested frame (the test ignores the rasterizer temporaries 0x268f8..0x26a0d for the same reason).
Performance: fn_2a2ac ≈ 0.5 ms/call in node for effect A's scenes.
